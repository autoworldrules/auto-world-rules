Your role is to generate new sets of rules used to construct graphs that pose challenging reasoning problems. Your final response must contain the entire set of created rules in an lp file.
I'm looking for an interesting rule base that can be used for evaluating the reasoning abilities of AI models. The rule base should be encoded using Answer Set Programming (ASP) syntax. In particular, it can contain the following types of rules.
Facts have the following form.
r(a,b).
This fact states that the relationship r holds between the objects a and b.
r(a,a) can also be written r(a).
Next, standard rules have the following form:
r(X,Z) :- u(X,Y), v(Y,Z).
r(X,X) can also be written r(X).
Here X,Y,Z are variables. The rule states that when X is in relation u with Y, and Y is in relation v with Z, then X is in relation r with Z. The number of conditions in a rule can vary. For instance, the following are also valid examples of rules:
r(X,Y) :- s(Y,X).
r(X,Y) :- u(X,Y), v(Y,Z).
Rules may contain constraints such as
r(X,Y) :- s(Z,X), s(Z,Y), X != Y.
Additional constraints for this project :

Relations must not have more than two arguments.
- A relation must appear in your final answer only if it is used in more than one rule.
- Note that we are interested in the creation of rule bases that pose reasoning challenges beyond hierachies and transitivity. The rules must be connected, and connected in various ways so that the reasoning challenges are diverse.
- Do not use any numerical value in the rules. For example ":- reviewer(R), #count { P : assigned(R, P) } > 2." is not acceptable.
- Name the relations with arbitrary variable names, e.g. r, s or u.
- Your final response must be a complete list of all the rules of the world you created and may eventually contain comments.

Please create a rule base as small as possible, which describes some domain of interest and which is likely to be challenging for AI models.I  give you two examples of worlds with many rules, Iron Coast and NoRa. Please try to design a third smaller world that has no choice rule or negation as failure, and allows the generation of problems that are harder than the ones that can be sampled from those two worlds.

Additional instruction:

Das et al. (2025) introduced two  difficulty metrics, both of which capture the intuition that off-path reasoning is harder than path-based reasoning. Let's add a third difficulty metric, OPEEC.

- The Off-Path Edge Count (OPEC) is defined as the number of triples that
are used to infer r(e, f ) which do not correspond to an edge of a path from e to f .

- The Backtrack Load (BL) instead measures the amount of off-path reasoning based on the close relation between inference depth and path length. It is defined as the ratio of the number of inference steps to the number of entities involved. The higher this ratio, the more the reasoning process intuitively deviates from path-based reasoning.

- Off-Path Entailed Edge Count (OPEEC) as the number of entailed off-path edges that are used to derive the answer of a query on a graph.

Create a rule base that is likely to generate high OPEC queries.
